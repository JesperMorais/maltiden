Two targeted fixes:

**1. Replace MD5 with FNV for shopping item IDs (PERF-16):**
In `backend/internal/services/shopping_service.go`, find the `generateItemID` function that uses `crypto/md5`. Replace with `hash/fnv`:
```go
func generateItemID(menuID, name, unit string) string {
    h := fnv.New64a()
    h.Write([]byte(menuID + "_" + strings.ToLower(name) + "_" + unit))
    return fmt.Sprintf("item_%x", h.Sum64())
}
```
Remove `"crypto/md5"` import, add `"hash/fnv"` import.

Note: This changes the item ID format. Existing shopping list items in the database will have MD5-based IDs. New items will have FNV-based IDs. This is fine — shopping lists are regenerated per menu, and old menus aren't re-fetched. No migration needed.

**2. Recipe shuffle for menu variety (DATA-10):**
In `backend/internal/services/menu_service.go`, the current logic picks `recipes[rand.Intn(len(recipes))]` in a loop, allowing duplicates. Replace with a shuffle-based approach:

```go
// Shuffle recipes for variety, cycle if fewer recipes than days
shuffled := make([]domain.Recipe, len(recipes))
copy(shuffled, recipes)
rand.Shuffle(len(shuffled), func(i, j int) { shuffled[i], shuffled[j] = shuffled[j], shuffled[i] })

// Assign recipes cycling through shuffled list
recipeIdx := 0
for i := 0; i < days; i++ {
    if !skipDays[date] {
        day.RecipeID = shuffled[recipeIdx % len(shuffled)].ID
        recipeIdx++
    }
}
```

Use `math/rand/v2` instead of `math/rand` for the modern Go idiomatic approach. `rand.Shuffle` is available in both — use `rand.Shuffle` from `math/rand/v2` if the import is cleaner, otherwise `math/rand` is fine (Go 1.24 auto-seeds).

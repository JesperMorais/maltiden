<objective>
Optimize SQLite database configuration and query patterns — enable WAL mode, configure connection pool, fix N+1 query in shopping list generation, add pagination to recipe listing, and add context timeouts to all storage methods.

Purpose: Database is the second major performance bottleneck. WAL mode enables concurrent reads during writes. Connection pool prevents "database locked" errors. Batch fetching eliminates N+1 (5 queries → 1 for a 5-day menu). Context timeouts prevent runaway queries from blocking the server.
Output: Optimized db.go configuration, batch recipe fetching, paginated GetAll, context-aware storage methods.
</objective>

<task type="auto">
  <name>Task 1: Enable WAL mode and configure connection pool</name>
  <files>backend/internal/storage/sqlite/db.go</files>
  <action>
In the `Open` function, after the foreign keys PRAGMA, add:

1. `PRAGMA journal_mode=WAL` — enables concurrent reads during writes. Verify result is "wal" (SQLite returns the new mode).
2. `PRAGMA synchronous=NORMAL` — safe with WAL, reduces fsync calls.
3. `PRAGMA busy_timeout=5000` — wait 5s instead of failing immediately on lock contention.

After PRAGMAs, configure the connection pool on `*sql.DB`:
4. `db.SetMaxOpenConns(25)` — conservative for SQLite (single writer, multiple readers with WAL).
5. `db.SetMaxIdleConns(5)` — keep a few warm connections.
6. `db.SetConnMaxLifetime(5 * time.Minute)` — recycle connections periodically.

Add `"time"` to imports. Keep the existing foreign_keys PRAGMA and Ping() call.

Order: Open → Ping → PRAGMA foreign_keys → PRAGMA journal_mode → PRAGMA synchronous → PRAGMA busy_timeout → SetMaxOpenConns → SetMaxIdleConns → SetConnMaxLifetime → runMigrations.
  </action>
  <verify>go build ./... compiles. Run server briefly and check it starts without PRAGMA errors.</verify>
  <done>WAL mode enabled, synchronous=NORMAL, busy_timeout=5s, connection pool configured (25 open, 5 idle, 5min lifetime).</done>

4. Return `map[string]*domain.Recipe` keyed by recipe ID.
5. Reuse the same JSON unmarshaling logic from GetByID.

**In shopping_service.go:**
Refactor `GetShoppingList` to eliminate N+1:
1. After fetching menu days, collect all unique recipe IDs from non-skip days.
2. Call `s.recipeStorage.GetByIDs(recipeIDs)` once (1 query instead of N).
3. In the loop, look up recipes from the returned map instead of calling GetByID per day.

This changes 5 queries (for a 5-day menu) to 1 query. Keep the same aggregation logic.

Also add `GetAllPaginated(filter *domain.RecipeFilter, limit, offset int) ([]domain.RecipeSummary, int, error)` to recipe_storage.go:
1. Same filter logic as GetAll.
2. Add `LIMIT ? OFFSET ?` to query.
3. Run a separate `SELECT COUNT(*)` with the same WHERE clause to get total count.
4. Return (recipes, totalCount, error).
5. Default limit: 50 if limit <= 0. Max limit: 200.
6. Keep the existing `GetAll` method unchanged for backwards compatibility (menu generation uses it).

<task type="auto">
  <name>Task 3: Add context timeouts to all storage methods</name>
  <files>backend/internal/storage/sqlite/recipe_storage.go, backend/internal/storage/sqlite/menu_storage.go, backend/internal/storage/sqlite/shopping_storage.go, backend/internal/storage/sqlite/household_storage.go, backend/internal/storage/sqlite/user_storage.go</files>
  <action>
Add 5-second context timeouts to all storage query methods:

1. In each storage method that runs queries, create a context: `ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)` followed by `defer cancel()`.
2. Replace `s.db.Query(...)` with `s.db.QueryContext(ctx, ...)`.
3. Replace `s.db.QueryRow(...)` with `s.db.QueryRowContext(ctx, ...)`.
4. Replace `s.db.Exec(...)` with `s.db.ExecContext(ctx, ...)`.
5. For transaction methods (like MenuStorage.Create), create context before `s.db.BeginTx(ctx, nil)` and use `tx.ExecContext(ctx, ...)`.

Add `"context"` and `"time"` to imports in each file.

Do NOT change method signatures — callers remain unchanged. The context is created internally in each storage method. Phase 7 may later propagate context from handlers.

Apply to ALL storage files: user_storage.go, household_storage.go, recipe_storage.go, menu_storage.go, shopping_storage.go.
  </action>
  <verify>go build ./... compiles. go vet ./... passes. Grep for remaining db.Query/db.QueryRow/db.Exec calls (should be zero outside of runMigrations and PRAGMA setup).</verify>
  <done>All storage methods use QueryContext/ExecContext/QueryRowContext with 5-second timeouts. No raw Query/Exec calls remain in storage methods.</done>

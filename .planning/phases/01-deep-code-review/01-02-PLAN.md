  <action>
Read each service file completely. For each service, check:

**auth_service.go:**
- Registration flow: Is household + user + member creation atomic? (Known concern: not transactional)
- Password validation: What's checked? Minimum length only? Max length? (bcrypt 72-byte limit)
- Email normalization: Case sensitivity? Whitespace trimming? Format validation?
- Login: Timing attacks (does "user not found" return faster than "wrong password")?
- Token claims: What goes into JWT? Correct householdID at time of login?

**household_service.go:**
- Invite code generation: Is it random enough? Length? Character set? Collision risk?
- Join flow: Can a user join multiple households? What happens if they try?
- Role management: Can you remove the last owner? Can you change your own role?
- Member removal: Authorization checks — who can remove whom?
- Error patterns: Sentinel errors vs string matching (known concern)

**recipe_service.go:**
- Create/Update validation: Required fields? Field length limits? Ingredient validation?
- Delete: Cascade behavior — what happens to menus referencing deleted recipes?
- Household scoping: Are recipes scoped to household or global?

**menu_service.go:**
- Generation algorithm: Edge cases — what if fewer recipes than days? Zero recipes? Duplicates?
- Random selection: Predictability concerns? Fairness of distribution?
- Menu-recipe relationship: What happens if referenced recipe is deleted?

**shopping_service.go:**
- Aggregation logic: Ingredient merging correctness (same ingredient, different units?)
- Quantity parsing/arithmetic: Floating point issues? String-to-number conversion?
- N+1 query pattern (known concern): Verify and assess impact

**tjek_service.go:**
- External API error handling: What happens on timeout? 500? Rate limit? Malformed response?
- Data parsing: Are external API responses validated before use?
- Bubble sort (known concern): Verify location and impact
- Sequential fetching (known concern): Verify and assess

<task type="auto">
  <name>Task 2: Review storage layer, migrations, and entry point for SQL injection, data integrity, and startup safety</name>
  <files>backend/internal/storage/sqlite/db.go, backend/internal/storage/sqlite/user_storage.go, backend/internal/storage/sqlite/household_storage.go, backend/internal/storage/sqlite/recipe_storage.go, backend/internal/storage/sqlite/menu_storage.go, backend/internal/storage/sqlite/shopping_storage.go, backend/migrations/*.sql, backend/cmd/server/main.go</files>
  <action>
Read each storage file and migration completely. Check:

**All storage files — SQL injection:**
- Are ALL queries parameterized? Look for string concatenation in SQL queries
- Are any user inputs interpolated directly into SQL strings?
- Pay special attention to `IN (...)` clauses, `ORDER BY`, and `LIKE` patterns

**All storage files — data integrity:**
- Are NULL checks correct? (`sql.NullString`, `sql.NullInt64` usage)
- Are `sql.ErrNoRows` handled consistently? (Convention: return nil, nil)
- Are `Scan` field orders matching `SELECT` column orders?
- Are timestamps handled correctly? (UTC? Timezone-aware?)

**All storage files — resource management:**
- Are `rows.Close()` calls deferred after `Query()`?
- Are `rows.Err()` checked after iteration?
- Are prepared statements closed?

**db.go — migration system:**
- Migration execution: Is it idempotent? What happens on partial failure?
- Migration ordering: Is it deterministic?
- File path handling (known concern): Relative paths, working directory dependency
- WAL mode: Is it enabled? Should it be for concurrent reads?

**Migrations — schema review:**
- Foreign key constraints: Are they defined? Are they enforced? (SQLite requires `PRAGMA foreign_keys = ON`)
- Index coverage: Are frequently queried columns indexed?
- Data type choices: Appropriate for the data?
- NOT NULL constraints: Are they on required fields?
- DEFAULT values: Sensible for optional fields?
- CHECK constraints: Present where needed?

**main.go — startup:**
- Environment variable handling: What's required? What has defaults? What fails silently?
- Database initialization: Error handling on Open, migration failure
- Graceful shutdown: Does it exist? What about in-flight requests?

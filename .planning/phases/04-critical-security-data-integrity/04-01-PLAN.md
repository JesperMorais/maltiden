<task type="auto">
  <name>Task 1: Harden JWT — validate secret at startup, pin HS256 algorithm</name>
  <files>backend/pkg/utils/jwt.go, backend/cmd/server/main.go</files>
  <action>
  **jwt.go changes:**
  1. Remove package-level `var jwtSecret = []byte(os.Getenv("JWT_SECRET"))` — this reads env at package init, too early and untestable.
  2. Add a package-level `var jwtSecret []byte` (uninitialized).
  3. Add `func InitJWTSecret(secret string) error` that validates `len(secret) >= 32`, sets `jwtSecret = []byte(secret)`, and returns error if too short or empty. This is called once from main.go.
  4. In `ValidateToken`, add algorithm validation in the keyfunc callback: check `token.Method.Alg() == "HS256"`, return error `fmt.Errorf("unexpected signing method: %s", token.Method.Alg())` if not. This prevents the "none" algorithm attack (AUTH-03).
  5. In `GenerateToken`, add a guard: if `len(jwtSecret) == 0` return error — defensive check in case InitJWTSecret wasn't called.

  **main.go changes:**
  1. Read `JWT_SECRET` from env at top of main().
  2. Call `utils.InitJWTSecret(jwtSecret)` — if error, `log.Fatal("JWT_SECRET must be at least 32 characters")`.
  3. Place this BEFORE database open so the server fails fast on misconfiguration.

  **Avoid:** Don't change the Claims struct or token expiry — those are unrelated to this fix.
  </action>
  <verify>
  `cd backend && go build ./...` compiles successfully.
  Manually verify: without JWT_SECRET env var, `go run ./cmd/server` should fail with clear error message.
  </verify>
  <done>
  - Server fails to start if JWT_SECRET is empty or < 32 characters
  - ValidateToken rejects tokens with non-HS256 algorithms
  - GenerateToken refuses to sign with empty secret
  - go build passes
  </done>
</task>

<task type="auto">
  <name>Task 2: Add auth middleware to shopping list endpoints</name>
  <files>backend/internal/api/router.go, backend/internal/api/handlers/shopping.go</files>
  <action>
  **router.go changes:**
  1. Change the two shopping routes from `mux.HandleFunc` (public) to `mux.Handle` with `middleware.RequireAuth` wrapper — same pattern as all other protected routes.
  2. `GET /shopping-list` → `mux.Handle("GET /shopping-list", middleware.RequireAuth(http.HandlerFunc(shoppingHandler.GetShoppingList)))`
  3. `PATCH /shopping-list/items/{id}` → same RequireAuth wrapping.

  **shopping.go changes:**
  1. In `GetShoppingList`, add at the top: extract `householdID` from auth context via `middleware.GetHouseholdID(r.Context())`, return 401 if empty. This householdID will be used for IDOR protection in Plan 02.
  2. In `UpdateItem`, add same householdID extraction and 401 check.
  3. Use `r.PathValue("id")` instead of manual `strings.Split` path parsing for `UpdateItem` — Go 1.22+ mux supports this natively since the route already uses `{id}` pattern (fixes VALID-03 for this handler).

  **Avoid:** Don't add IDOR verification yet (menu belongs to household) — that's Plan 02. Just add the auth gate here.
  </action>

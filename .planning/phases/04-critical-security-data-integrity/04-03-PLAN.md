  <name>Task 1: Enable foreign keys and fix SQL safety issues</name>
  <files>backend/internal/storage/sqlite/db.go, backend/internal/storage/sqlite/recipe_storage.go, backend/internal/storage/sqlite/household_storage.go</files>
  <action>
  **DATA-04: Enable foreign keys in db.go:**
  1. In `Open()`, immediately after `db.Ping()` and BEFORE `runMigrations()`, add:
     ```
     if _, err := db.Exec("PRAGMA foreign_keys = ON"); err != nil { return nil, fmt.Errorf("enable foreign keys: %w", err) }
     ```
  2. This must run on EVERY connection. Since database/sql pools connections, also set via the connection DSN: change `sql.Open("sqlite3", path)` to `sql.Open("sqlite3", path+"?_foreign_keys=on")` — this ensures FK enforcement even for pooled connections. Keep the PRAGMA as a verification step.

  **DATA-03: Fix tag filter JSON injection in recipe_storage.go:**
  1. In `GetAll`, the tag filter currently uses `LIKE "%\"" + filter.Tag + "\"%"` which is vulnerable to JSON injection (a tag containing `"` breaks the filter).
  2. Replace with SQLite JSON1 `json_each()` approach:
     ```sql
     AND id IN (SELECT r2.id FROM recipes r2, json_each(r2.tags) WHERE json_each.value = ?)
     ```
  3. Pass `filter.Tag` as a parameterized value (not string concatenation).
  4. This is both safer (parameterized) and more correct (exact match vs partial LIKE).

  **DATA-05: Fix UpdateMemberStatus string concatenation in household_storage.go:**
  1. Current code builds SQL via `strings.Join(updates, ", ")` — while the column names are hardcoded (not user input), the pattern is fragile and not idiomatic.
  2. Replace with two explicit queries: one for `is_eating_today` only, one for `wants_lunch_box` only, one for both. Use a simple if/else chain:
     - Both non-nil: `UPDATE household_members SET is_eating_today = ?, wants_lunch_box = ? WHERE household_id = ? AND user_id = ?`
     - Only isEatingToday: `UPDATE household_members SET is_eating_today = ? WHERE household_id = ? AND user_id = ?`
     - Only wantsLunchBox: `UPDATE household_members SET wants_lunch_box = ? WHERE household_id = ? AND user_id = ?`
  3. Convert bool to int (0/1) inline — same as current code.

  **Avoid:** Don't change migration files that already ran. Only add new migration files.
  </action>
  <verify>
  `cd backend && go build ./...` compiles.

  Check recipe_storage.go: no LIKE with string concatenation for tags.

  </verify>
  <done>

  - Tag filter uses json_each() with parameterized query — no injection possible
  - UpdateMemberStatus uses explicit query variants — no string building
